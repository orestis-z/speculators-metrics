# Grafana dashboards

Two dashboards, generated by `gen_dashboards.py`:

| uid | Title | Content |
| --- | --- | --- |
| `speculators-ci-bench` | Speculators CI · Training benchmarks | Step time, throughput, peak memory, fetch share; stacked step breakdown (fetch / fwd / bwd / clip / opt) per test and environment |
| `speculators-ci-acceptance` | Speculators CI · Acceptance | Latest acceptance length per test; per test file: acceptance length over time and acceptance by draft position |

Filters: Branch (default `main`), Environment (Python + vLLM, default `py3.12 / vLLM latest`), Test, and Test file (acceptance only, defaults to the `regression/` suites).

Edit `gen_dashboards.py`, not the JSON, and not the dashboards in the Grafana UI.

## Files

| Path | |
| --- | --- |
| `gen_dashboards.py` | Source of truth. Writes `dashboards/*.json` and `k8s/speculators-ci-grafana.yaml`. |
| `dashboards/*.json` | Generated dashboard JSON, for import or `push.sh`. |
| `k8s/speculators-ci-grafana.yaml` | Generated Grafana Operator `GrafanaDatasource` + `GrafanaDashboard` CRs. Fill in the `instanceSelector` label before applying. |
| `push.sh` | Uploads `dashboards/*.json` through the Grafana HTTP API (overwrites by uid). |
| `test_queries.py` | Runs every dropdown query and main query against a Grafana and prints options and row counts. |

## Workflow

```bash
python grafana/gen_dashboards.py

# optional: check the queries against a scratch Grafana (same versions as the cluster)
docker run -d --name grafana-test -p 127.0.0.1:3300:3000 \
  -e GF_PLUGINS_PREINSTALL_SYNC=yesoreyeram-infinity-datasource@4.1.8 \
  -e GF_AUTH_ANONYMOUS_ENABLED=true -e GF_AUTH_ANONYMOUS_ORG_ROLE=Admin \
  grafana/grafana:13.0.1
curl -s -X POST http://127.0.0.1:3300/api/datasources -H 'Content-Type: application/json' \
  -d '{"name":"speculators-metrics","type":"yesoreyeram-infinity-datasource","uid":"dg3hq8oc1y8e8c","access":"proxy","jsonData":{}}'
python grafana/test_queries.py http://127.0.0.1:3300
grafana/push.sh http://127.0.0.1:3300

# deploy: apply k8s/speculators-ci-grafana.yaml, or push through the API, e.g.
grafana/push.sh https://<grafana-host> -H "Cookie: <session cookie>"
```

The dashboards need the Infinity plugin and an Infinity datasource with uid `dg3hq8oc1y8e8c`.

## Gotchas

These cost time when building the dashboards; keep them in mind when editing.

- **JSONata locals vs. dashboard variables.** Grafana treats any `$name` in a query as a dashboard variable reference when a variable of that name exists. A JSONata local called `$env` or `$test` gets replaced with the dropdown value and creates a variable dependency cycle, and nothing loads. Locals here use other names (`$envLabel`, `$testLabel`).
- **Regex values in transformations.** Grafana 13 interpolates panel transformations by `JSON.stringify` → replace variables → `JSON.parse`. `${var:regex}` turns `3.11` into `3\.11`, which is invalid JSON, and the transformation silently stops updating. All dropdown filtering is therefore done inside the Infinity query (`field in [${var:doublequote}]`). Transformations only compare single repeat values for equality.
- **Time range.** Infinity does not apply the dashboard time range by itself. `$toMillis` in the plugin's JSONata engine drops the time of day, so the query compares the ISO timestamp strings against `${__from:date:iso}` / `${__to:date:iso}`. That is exact because every record's timestamp is UTC `...+00:00`.
- **One download per panel set.** Panel 1 runs the Infinity query; the other panels reuse its result through the `-- Dashboard --` datasource. Each dropdown is one more download of `metrics.json`. Many parallel downloads of the full file ran the Grafana pod out of memory once.
- **Test file default.** Grafana defaults are fixed values, so new `tests/e2e/regression/` files must be added to `REGRESSION_FILES` to be selected by default.
